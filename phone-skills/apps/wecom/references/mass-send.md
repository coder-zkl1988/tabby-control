## 群发助手（1v1）

### 入口
- 底部「消息」tab 的会话列表里找「群发助手」条目（官方服务会话，非联系人；摘要形如「管理员通知你群发消息给客户」），点它进入。
- 列表里没有该条目 = 当前企业没有群发任务入口，直接汇报「无群发助手条目」。

### 页面结构（已验证：荣耀真机，企微 5.0.9）
- 标题「群发助手」居中，左上角返回，右上角三点菜单。
- 待发内容以卡片纵向时间线排列，无日期分组。每张卡片：
  - 卡片上方时间标注：**当天的卡片只显示时:分**（如「16:46」；12小时制设备显示「下午4:14」「上午9:00」，同样属于当天纯时间标注）；非当天的会带「昨天」、星期或具体日期字样（如「8月19日」，不带年份时按当年理解）。
  - **时间标注属于它下方那张卡片，不是上方那张。** 版式是「时间标注 → 该时间的卡片」自上而下配对（同微信消息时间戳）。读到一个时间标注后，要判定的是**紧接其下**的卡片；把标注算给它上面那张，就会把昨天的卡片当成今天的发出去——这是已发生过的错误。
  - 因此每张卡片的时间 = **向上找到的最近一个时间标注**。点「发送」前必须先确认这一条，卡片上下都有标注时以上方那个为准。
  - 发送者 + 标题（如「管理员通知你群发消息给客户」）。
  - 浅灰内嵌摘要框预览群发内容（文字与 [图片] 标记）。
  - 卡片底部通栏蓝色「发送」按钮。
- 页面水印含「账号 @企业」字样，可核对当前企业。
- **排列方向与朋友圈相反：最早在最上、最新在最底部**（聊天式时间线）。进入页面时默认停在底部，也就是**今天的卡片就在眼前**。
- **是否翻页，看当前屏有没有出现分界：**
  - 当前屏里已经能看到早于今天的卡片（带「昨天」或更早日期）→ **分界已可见，今天的卡片全在屏幕上，不用翻**。
  - 当前屏**全是今天的**卡片 → 说明今天的还没显示完，**向上翻看更早的内容**（`SCROLL direction:up` 小步逐屏），直到出现第一张早于今天的卡片、或到列表顶部，确定分界后再开始。
  - 翻页只为找分界，**不要一路翻到列表最顶部**——上面都是过期卡片，看它们没有意义，还会白白消耗步数。
  - 注意方向：朋友圈是今天在顶部、往下找分界；这里是今天在底部、往上找分界。别把两者搞混。

### 发送规则（时间锁定今天）
0. **先盘点后发送（强制第一步）**：进入群发助手后，第一动作是向列表顶部方向翻页（`SCROLL direction:up` 逐屏）直到出现早于今天的卡片或到达列表顶部，边翻边数清**今天卡片的总数和每张的时间标注**，记入 key_process 账本（如 `今日共3张：15:38/17:14/18:09`）。页面停在列表底部时只能看到最新的几张——**首屏可见 ≠ 今日全部**，没有完成盘点账本前禁止点击任何「发送」。进入当天卡片较少、一屏放得下时也要核对到列表顶部再开始。
   - **「无待办/无今日」必须附盘点证据**：结论为无待办时，汇报里必须写出翻页后见到的最新卡片时间标注原文（如 `已翻至列表顶部，最新一张为8月27日16:20 → 无9月3日卡片`）。没有盘点证据的「无待办」视为无效盘点，必须重新翻页核对后再下结论。
1. 逐张读卡片的时间标注：**只有显示纯时:分（当天，含「下午X:XX」12小时制样式）的卡片才允许点「发送」**。
2. 带有「昨天」、星期或具体日期字样的卡片属于非当天，**一律不点发送**，跳过并汇报。
3. 当天的卡片按时间先后逐张处理，即**从紧挨分界的那张（今天最早的一张）开始向下逐张**：点该卡片底部「发送」→ 等待结果提示 → **重新截图确认该卡片已从待发列表消失（或出现「已发送」标记）**后再处理下一张；不并发、不跳卡。每张发送成功后列表会重排（该卡片消失、下方卡片上移，时间标注随之移动）——必须基于**新截图**重新定位下一张的目标卡片和它的发送按钮，禁止沿用上一步的坐标直接点击。
4. 发送后卡片**仍在待发列表 = 没有发出**：重试一次，仍不消失就如实记为「发送失败」，**禁止凭点击过就计入已发送数**。核对方法：发送前先抄下该卡片摘要的前 10 个字，发送后的**新截图/页面结构参考**里这串文字不应再出现在待发卡片中；仍出现 = 未发出。卡片内容含小程序/链接时发送可能弹确认页——必须走到确认完成，不能只点了卡片上的「发送」就算发过。
5. 无法确定卡片是哪天的（时间被遮挡、截图不清、看不到它上方的时间标注）→ 不发送，跳过并在汇报中说明。判不准就不发，宁可漏发也不能错发给客户。
6. 全部处理完后重新进入/刷新页面核对：待发列表里应只剩非当天卡片；**把核对结果（剩余卡片数）写进汇报**。

### 汇报格式
- 完成前必须逐卡输出分类结果，每行：`卡片N | 上方时间标注=XX | 摘要=YY | 分类=今天已发送 或 今天发送失败 或 跳过(已取消/早于今天/无法确认)`。摘要必须抄该标注**下方**那张卡片的文案，用来自证配对没有错位。
- **数字必须对账**：最终汇报的「已发送N张」必须等于逐卡行里「今天已发送」的数量，且等于盘点账本总数 − 跳过数 − 失败数。三者对不上 = 汇报有错，先回去核对再汇报。没有逐卡行就禁止给出任何总数。
- 没有待发卡片时输出「群发助手无待发卡片」；最终汇报使用完整文字，禁止用省略号或「...」代替。

### 边界
- 只发送企业指派的待发卡片，不修改卡片内容，不新建群发。
- 群发触达真实客户：对卡片内容有疑问、或任务要求与卡片内容冲突时，停在发送前询问。
- 群发助手按企业隔离：任务要求“每个企业都执行”时，按「多实例与企业遍历」协议逐实例逐企业检查本页面。
