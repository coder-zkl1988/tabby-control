## 多实例与企业遍历

一台手机可能同时存在多个企业微信实例（应用分身），每个实例内可加入多个企业。任务要求“按企业执行”“每个企业都执行”时，必须遍历每个实例的每个企业，逐个执行，不能只做一遍。已验证环境：荣耀真机（MagicOS）+ 企业微信 5.0.9，桌面同屏并列两个同名图标，每个实例加入两个相同企业。

### 实例发现与启动
- 存在分身时，`AWAKE value:"com.tencent.wework"`（或「企业微信」）会弹出系统选择弹窗（已验证：无论企微是否已在前台都会弹出；荣耀弹窗标题「使用以下方式打开」），并排列出主应用与分身两个企微图标：**分身图标有蓝色数字分身角标（如「2」），主应用没有**。注意用分身角标识别分身，不要被红色未读角标误导。
- **启动指定实例的统一方式**：`AWAKE value:"企业微信" instance:"clone1"`（分身）或 `instance:"main"`（主应用）→ 再在弹窗中点击对应图标。点带分身角标的图标进分身，点不带分身标记的进主应用。不要回桌面翻图标（同名图标容易点错），不要用最近任务恢复。
- `instance` 参数的作用是**让设备端告诉你这台手机上有几个实例、分别叫什么**（AWAKE 的返回里会写明，如「该应用有 2 个实例：main、clone1」），并在返回里点名该点哪个图标。**它不保证跳过弹窗**：已验证荣耀 MagicOS 的分身框架无论如何都会弹选择框，此时返回会写「系统仍弹出实例选择框」并指明目标图标特征——按它点即可。只有返回明确写「已直接进入实例 X」时才表示无需再点。
- 切换实例 = 再次 AWAKE → 在弹窗中点另一个图标；弹窗每次都会出现，无论当前是否已在企业微信内。
- **这条规则由设备端强制执行，不是建议**：任务文本提到「分身」「主应用」「角标」「clone1」等特定实例时，若整个执行过程从未执行过 AWAKE，设备端会拒绝你的 COMPLETE 并说明原因；连续拒绝后任务直接判为 aborted。原因是分身与主应用界面完全相同，当前屏幕可能是上一个任务留下的，不能作为身处哪个实例的依据。
- **强制规则：凡是针对特定实例的任务，开始时必须走一遍 AWAKE 弹窗并点击目标实例的图标，即使任务文本声称「已在目标实例」「无需切换」「当前停在X企业」。任务文本对手机当前状态的描述不作为依据——设备层无法区分实例，只有弹窗点击能锚定身份。**
- **弹窗点错是高发错误（两个图标除角标外完全一样）：进入后必须核对身份，不符就纠正。** 流程：进入实例 → 打开抽屉读顶部账号名 → 与任务文本给出的目标账号（或此前枚举记录的实例-账号映射）比对 → **不符时重新 AWAKE 弹窗、点另一个图标、再次核对**（最多重试一次）→ 仍不符则 `ABORT value:"账号不符：看到X，期望Y"`（不要 CALL_USER 等待——超时后"自行继续"会把任务做在错误账号上）。把最终进入的实例账号名写进汇报，作为切换成功的证据。
- 弹窗点「取消」或按返回即放弃启动。只装了一个实例时通常无弹窗、直接打开。
- 两个实例的页面（消息/工作台/朋友圈）看起来几乎一样，**不能用页面内容判断身处哪个实例**；页面相同恰恰是没切换的信号，发现这种情况必须回到 AWAKE 弹窗重来。

### 企业枚举与切换
- 消息页左上角抽屉按钮打开侧边抽屉。抽屉内容：用户资料与当前企业（带勾选与认证标记）、其余企业行（各行带独立未读角标）、多设备登录、我的名片、高级功能、创建/加入企业、设置。
- 不同实例加入的企业清单可能相同。切换企业 = 在抽屉里直接点目标企业行：已验证无确认框、无验证页、无加载框，立即生效，消息/通讯录/工作台上下文随之切换。
- 切换后消息页和工作台顶部都不显示企业名。唯一可靠的当前企业验证方式：重新打开抽屉，看哪一行带勾选标记。每次切换后、每次执行任务前，都必须重开抽屉验证一次。
- 点目标企业行后若出现验证、重新登录、异常或加载失败页面：停止遍历，CALL_USER。

### 按企业遍历的执行协议
1. 通过 AWAKE 弹窗点击目标实例图标进入（每个实例的任务都必须重新走弹窗，不得沿用当前前台实例），打开抽屉，核对顶部账号名与指派实例一致，并记录：实例身份（点击的是哪个图标）、企业清单、当前选中企业（作为本实例的恢复点）。
2. 对清单中每个企业依次执行：当前不是该企业时先切换 → 重开抽屉验证勾选 → 执行任务 → 立即记录该企业的小结与失败原因，再进入下一个企业。
3. 该实例全部企业完成后，切回进入时记录的原始企业并验证。
4. AWAKE 唤起选择弹窗，启动下一个实例，重复 1-3。
5. 汇报必须按「实例 × 企业」逐条列出结果；某一组合失败或被跳过时显式说明原因，不得把多个企业的结果合并成一条总结。

### 边界
- 退出企业、退出登录、多设备管理、创建/加入企业、管理员设置仍是 CALL_USER 操作；遍历只做“切换 + 执行任务”。
- 各企业数据完全隔离：上一个企业看到的会话、审批、打卡结果不能当作下一个企业的依据；每个企业都要重新取证。
- 未读角标只反映该实例该企业的通知状态，不要把图标角标当成企业清单或任务结果的依据。
