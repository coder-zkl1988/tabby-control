# 小红书登录子技能

适用任务：用户要求打开小红书并通过手机号验证码登录。

前置能力：

- 未安装时依赖 `app.install.official_store`。
- 获取验证码时依赖 `sms.verification`。

## 安全和能力边界

- 手机号和验证码只能用于用户明确要求的本次登录，不得写入 `note`、`key_process`、日志或最终返回。
- Android 不保证第三方 App 能读到本机号码。页面没有可靠号码时使用 `CALL_USER`，不得猜测。
- 验证码查找和短信隐私边界由 `sms.verification` 系统 Skill 负责；本技能只负责小红书登录页面。
- 图形验证码、滑块、实名、人脸或账号风险验证必须 `CALL_USER`，不得绕过。
- 只勾选登录必需的用户协议，不得自行同意无关营销授权。

## 1. 打开并判断登录状态

1. 使用 `action:AWAKE value:"com.xingin.xhs"`。
2. 若动作结果明确显示未安装，交由 `app.install.official_store` 能力处理，安装后再返回本流程。
3. 能进入首页时点击底部“我”；看到个人主页、昵称和作品区，视为已登录。
4. 出现手机号登录入口时进入验证码登录。
5. 检测到其他账号已登录时，不得自动退出或切换，先 `CALL_USER` 确认。

## 2. 填写手机号并请求验证码

1. 选择“手机号登录/验证码登录”，不要改用密码登录。
2. 手机号来源顺序：任务明确提供 > 页面已显示且用户确认 > `CALL_USER` 获取。
3. 点击手机号输入框并输入；所有记录只写“手机号已填写”。
4. 勾选必要协议后点击“获取验证码”。按钮开始倒计时即表示请求已发送，不要重复点击。

## 3. 填写验证码

1. 按 `sms.verification` 系统 Skill 获取本次小红书验证码并返回小红书。
2. 确认当前仍是本次登录的验证码输入页，再填写验证码。
3. 验证码过期或错误时最多重新请求一次，不得连续试码。
4. 无法安全取得时 `CALL_USER value:"未能自动取得小红书验证码，请在手机上完成验证码输入"`。

## 4. 完成验证

- 登录后进入底部“我”，确认出现个人主页而不是登录入口。
- 兴趣选择、通知权限或青少年模式只处理进入主页所需步骤，其他选择跳过或稍后。
- 成功返回只说明“已完成登录并验证个人主页”，不得包含手机号、验证码或短信正文。
