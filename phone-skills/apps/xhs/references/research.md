# 内容研究浏览子技能（关键词搜索浏览 / 首页自然浏览 + 结构化记录）

适用任务：任务文本以「小红书内容研究任务」开头，或要求按关键词搜索并逐篇浏览、按首页推荐流自然浏览、带互动配置、要求返回 `RECORD_JSON`。这类任务由桌面端按"账号定位 + 关键词 + 篇数 + 停留区间 + 互动配置"生成，你的职责是**如实执行并如实记账**，不是凑数。

## 一、开工前先定账本（第一步就写进 key_process）
- 读出任务里的：模式（关键词搜索 / 首页自然浏览）、关键词、目标篇数 `n`、停留区间、每种互动的开/关与本次上限。
- 第一次输出的 key_process 固定格式：`模式=搜索「关键词」；目标 n 篇；已浏览 0/n；已互动 赞0/上限a 藏0/上限b 关0/上限c；已处理：`。
- 首页模式写 `模式=首页；目标 n 篇；…`。
- 之后每完成一篇都刷新这一行，**不要换格式**；结束时的 RECORD_JSON 直接从这一行的数字生成，账本和 JSON 必须一致。

## 二、进入列表
- 关键词模式：首页右上角放大镜 → `TYPE` 输入任务里的**实际关键词**（禁止输入"关键词"字样）→ 蓝色「搜索」或 `ENTER`。结果页信号：顶部有关键词、有「综合/最新/视频/图文」标签、下方双列瀑布流。
- 首页模式：确认在首页「发现」瀑布流即可（底部完整导航 + 双列卡片），不要搜索。**推荐流暂时和账号定位不匹配是新号的常态（养号的目的就是把它养匹配）：仍按目标篇数浏览完，优先挑最接近定位/兴趣池的卡片，实在没有就挑普通的生活方式图文（出行、美食、好物、家居都行），不要因为"没有相关内容"提前结束；匹配度写进结束时的 observation 即可。** 首页模式不记 `content_mismatch`。
- 搜索无结果（空页面、"没有找到相关内容"）：记 `no_results`，不要换词重搜，直接进入"结束"步骤汇报。
- 结果与关键词明显不相关（整屏都是无关内容）：记 `content_mismatch`，可以只浏览 1–2 篇相关的就结束，如实写 browsed。

## 三、单篇浏览标准（每篇必须做到，否则不计数）
1. 挑一张**未处理过**的卡片（看 key_process 已处理清单，不靠记忆）：优先与关键词/账号定位相关、图文帖、有一定点赞数；跳过广告、直播、带货专场、用户主页。
2. 进入详情后**第一个动作必须是 `WAIT value:"2"`**，看清标题、作者、正文首屏。
3. 阅读正文：正文折叠有「展开」先展开；做 1–3 次慢速向上滑（`SCROLL direction:down`，**distance 在 250–650 之间变化**，例如 300、520、410——不要每次都写同一个值），每次滑后 `WAIT` 1–4 秒，**时长要变化**（例如 2、3、1），不要每篇一样。
4. 进入评论区并读到末尾：继续慢滑，直到明确看到评论区末尾或“没有更多”一类信号；0 条评论也可以完成，但必须确认确实没有评论。记录实际看到的 `commentsRead`，并且只有确认读到末尾时才能记录 `commentsComplete:true`；无法确认读完时该篇不计入 `browsed`。
5. 停留时长：任务给的区间（例如 10–25 秒）由 WAIT 和滑动共同凑够；从进入详情到返回列表按实际动作累计秒数，写入该帖 `dwellSeconds`。**禁止连续 3 次以上只 WAIT 不滑动**，也禁止连续 4 步屏幕完全不变（会被判定卡死）。图文帖靠"滑一下 + 等一下"交替；视频帖画面本身在变，仍需满足任务给定的最短停留秒数。
6. 全屏竖向视频流（底部心形/星形/评论气泡，没有顶部搜索框）：上下滑会切换视频，**禁止竖向滑动**；点评论气泡中心，读到评论区末尾后 `BACK` 关面板，再 `BACK` 回列表。无法确认评论区已读完时不计数。
7. 看完决定是否互动（见四），然后 **一次 `BACK`** 返回列表，`WAIT value:"1"` 后看新截图确认已回到结果页/首页（顶部关键词 + 瀑布流，或首页导航 + 瀑布流）。看到「历史记录」「猜你想搜」说明多退了一层：点历史里的原关键词回到结果页。
8. 确认回到列表后，key_process 追加这一篇：`已处理：…；标题[仅浏览]` 或 `标题[赞]`/`[赞+藏]`，并把 `已浏览 x/n` 加一。**再滑动一屏让看过的卡片离开屏幕**，然后挑下一张。

### 像真人一样"不是每篇都点"（脑图要求）
- **随机跳过**：列表里每看到 3–5 张相关卡片，至少让 1–2 张只在屏幕上滑过、不点进去（大约跳过 20–40%），跳过的卡片不记账、不算 `skipped`（`skipped` 只统计点进去但没计数的）。挑哪张跳过要变化：有时跳第 1 张，有时跳中间的，不要固定"每隔一张"。
- **列表滑动距离随机**：在结果页/首页滑动时 `SCROLL distance` 也在 250–650 之间变化，偶尔小滑一下（250–300）只露出半张卡片再决定点不点。
- **首页模式定期刷新**：首页自然浏览每看完 3–5 篇，回到顶部刷新一次切换推荐内容——在首页顶部再做一次 `SCROLL direction:up distance:400`（下拉刷新），或点底部「首页」tab 回顶；刷新后 `WAIT value:"2"` 看新卡片，再继续挑。刷新不算浏览篇数，但每次都要累加 key_process 的 `已刷新 x 次`，最终写入顶层 `refreshCount`。关键词模式不刷新且 `refreshCount` 必须为 0。

## 四、互动（少而准，严格按配置）
- 只有任务写"开"的动作可以做；写"关"或没写的一律不做。评论、发布、私信、分享**永远禁止**——误入评论编辑器立即 `BACK`，不输入任何文字。
- 每种动作有"本次最多 k 次"，达到就不再做，即使后面遇到更好的帖子。
- 第 1、2 篇纯浏览；互动帖之间至少隔 1 篇纯浏览；只挑与关键词/账号定位强相关、内容本身值得的帖子；多数帖子只看不互动。
- 点赞：点心形 → 确认变红才算；已经是红色不再点、不计数。收藏：点星形 → 确认高亮。关注：进作者卡片区的「关注」→ 确认变成「已关注」。互动后看一眼新截图再返回。
- 出现"操作过于频繁""请稍后再试"等提示：记 `rate_limited`，**立即停止所有互动**并进入"结束"步骤。

## 五、异常分类（只能用这几个 type）
| type | 何时记录 | 处置 |
|---|---|---|
| `no_results` | 搜索无结果 | 直接结束本关键词 |
| `load_failed` | 空白页/加载失败/网络错误 | `WAIT value:"5"` 重试一次，仍失败记录并结束 |
| `login_required` | 出现登录页、手机号登录、验证码 | 记录后立即结束，不要登录 |
| `account_restricted` | 账号异常/受限/需验证身份提示 | 记录后立即结束 |
| `rate_limited` | 操作频繁、稍后再试 | 停止互动，记录后结束 |
| `content_mismatch` | 结果整体与关键词不相关 | 少浏览，如实记 browsed |
| `interrupted` | 弹窗/来电/被切走导致无法继续 | 记录后结束 |
| `other` | 其他 | 写清 detail |
`detail` 用一句话写清屏幕上看到了什么。

## 六、结束与 RECORD_JSON（结构化记录，桌面端只认这一行）
触发结束：`已浏览` 达到 `n`；或列表再滑两屏也没有新的相关卡片；或出现需要立即结束的异常。
1. 先确认回到结果页/首页，再按通用规则 `HOME` 回桌面。
2. `COMPLETE` 的 `return` 分两部分：
   - 前 3–6 行人读汇报：模式与关键词、浏览 x/n、互动计数、异常、一句观察（内容与账号定位是否匹配、结果页以什么类型内容为主）。
   - **最后一行**必须是 `RECORD_JSON:` 紧跟一行紧凑 JSON，单行、双引号、不加注释、不加句号，之后不再写任何字：
```
RECORD_JSON:{"v":1,"mode":"search","keyword":"亲子酒店","planned":1,"browsed":1,"skipped":0,"refreshCount":0,"interactions":{"like":1,"collect":0,"follow":0},"anomalies":[],"posts":[{"title":"北京周边亲子酒店测评","author":"某某","action":"like","commentsRead":8,"dwellSeconds":21,"commentsComplete":true,"commentWorthy":true,"summary":"测评了三家北京周边带儿童乐园的酒店，价格和早餐都写了"}],"observation":"结果以酒店测评为主，与定位匹配"}
```
字段规则：`mode` 取 `search`/`home`（首页模式 `keyword` 写 `null`）；`planned` 是任务目标篇数；`browsed` 是真正计数的篇数（与账本一致）；`skipped` 是点进去但没计数的篇数；`refreshCount` 是首页真实刷新次数（搜索模式固定为 0）；`interactions` 只填已确认成功的次数；`anomalies` 是 `{"type":"…","detail":"…"}` 数组，没有就 `[]`；`posts` 必须与计数的帖子一一对应，`posts.length` 必须等于 `browsed`。每篇 `title` 不超过 20 字，`action` 取 `like`/`collect`/`follow`/`none`（多个动作写主要的一个），`commentsRead` 是实际看到的评论条数，`dwellSeconds` 是实际停留秒数且不得低于任务最短值，`commentsComplete` 只有确认评论区读到末尾/没有更多时才写 `true`；`commentWorthy` 是"这帖值不值得以后评一句"的**标注**（图文、与账号定位强相关、评论区氛围正向、不是广告/争议帖 → `true`，其余 `false`；**只标注，本任务绝不评论**）；`summary` 是正文一句话（≤60 字，说清帖子讲了什么，视频帖无正文写 `""`）；`observation` 一句话。
3. 所有字段必须对账：`planned` 等于任务目标篇数，`browsed` = 账本 `已浏览` 的 x = `posts.length`，`interactions` = 账本里的赞/藏/关计数，`refreshCount` = 账本刷新次数。任一帖子缺 `dwellSeconds`/`commentsRead`/`commentsComplete:true`、停留不足、评论区未确认读完或数字对不上时，不得报告 completed；应如实记录异常并失败结束。**禁止把没做的互动或没看完的帖子写进 JSON**。

## 七、防卡死与节奏
- 不要在同一坐标重复点击：点了没变化就先滑动再瞄新卡片封面中心。
- 连续 4 步截图不变会被判卡死：WAIT 之间必须夹滑动或点击。
- 每篇的滑动次数、停顿秒数、滑动距离、是否横滑要随内容变化；正文短就少滑，讨论多就多停；连续两次 `SCROLL` 不要用完全相同的 distance。
- 返回后小红书保留滚动位置，刚看过的卡片还在原位——先滑再选，不要就近点。
