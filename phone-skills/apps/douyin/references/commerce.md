# 商城与团购子技能

适用任务：浏览抖音商城、团购、商品、店铺、购物车、订单、优惠券、退款或售后。

## 进入与定位
- 首页顶部可能有“商城”和“团购”频道；侧边栏也可能有钱包、券包、附近团购等入口。
- 商城页通常仍保留抖音顶部频道与底部导航，并可能有商城搜索和购物车角标。
- 根据任务选择入口：找商品用商城搜索，找本地服务用团购，查已购内容用订单/售后。

## 只读浏览
- 浏览商品、价格、店铺、评价或团购规则可以只读进行。
- 商品信息会动态变化；报告时区分页面标价、券后价、规格价、预估到手价和直播口播价，不自行合并。
- 查看多个商品时在 `key_process` 记录商品名、规格和当前价格，避免重复。
- 不读取或回显无关的收货地址、手机号、订单号、支付方式或钱包余额。

## 会改变账号的操作
- 领取优惠券、加入购物车、关注店铺、提交订单、联系商家、退款和售后都会改变账号状态，只有用户明确要求时执行。
- 选择商品前确认规格、数量、店铺和价格；不要默认选择页面第一个规格。
- 进入购物车或订单页时只处理用户指定条目，不清理其他商品或历史订单。

## 资金与不可逆边界
- 到“提交订单 / 确认支付 / 立即购买 / 确认退款 / 取消订单 / 确认收货”等最终按钮前，必须 `CALL_USER`，并汇总商品或服务、规格、数量、总价、地址/门店和付款动作。
- 不输入支付密码、短信验证码或实名信息；交给用户完成。
- 支付返回、HTTP 成功或页面跳转都不等于交易成功。必须在订单详情确认订单状态、金额和商品，再报告结果。
- 退款/售后要区分“已申请”“商家处理中”“退款成功”，不能把提交申请说成退款完成。

## 退出
- 未提交订单时用 `BACK` 返回商城列表；若出现保留订单/放弃支付弹窗，停止并按用户选择处理。
